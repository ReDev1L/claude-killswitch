# claude-killswitch

Kill switch для одного сервиса: трафик к Anthropic (Claude Code, claude.ai, их CDN) выходит из машины **только через VPN-туннель** — в Windows и в WSL2. Если туннеля нет, соединение падает, а не уходит напрямую. Остальной трафик не затрагивается и идёт по правилам VPN-клиента.

Подробный разбор решений, грабли, результаты проверок и диагностика — в [claude-killswitch-handoff.md](claude-killswitch-handoff.md).

## Как это работает

- **Windows.** Одно исходящее правило брандмауэра Block для всех программ на адреса Anthropic (`160.79.104.0/21`, `2607:6bc0::/48` и IP трёх CDN-хостов). Правило действует на всех интерфейсах, **кроме туннелей** и loopback. Когда VPN поднят, маршрут ведёт в туннель, и правило не срабатывает. Когда VPN упал, соединение получает отказ `WSAEACCES` ещё до первого пакета.
- **WSL2.** Обычный брандмауэр трафик WSL не видит, поэтому для WSL ставится пара правил Hyper-V firewall: Block всем и Allow с IP-адресов туннелей с более высоким приоритетом. Работает в mirrored-режиме сети WSL.
- **Автообновление.** Задача Планировщика от SYSTEM пересобирает правила при каждом подключении и отключении сети (события 10000/10001 журнала `NetworkProfile`), при старте системы и раз в сутки.

## Требования

- Windows 10/11. Для части про WSL нужны Windows 11 22H2+, WSL 2.0.9+ и `networkingMode=mirrored`.
- Права администратора для установки.
- VPN-клиент, который создаёт сетевой адаптер (WireGuard, wintun, TUN-режим Xray/sing-box) и **маршрутизирует адреса Anthropic в туннель**.

## Быстрый старт

1. Проверьте имена туннельных адаптеров (`Get-NetAdapter`) и при необходимости поправьте значение по умолчанию `-VpnAlias` в скрипте. Сейчас там `AmneziaVPN`, `happ-*`, `tun2*`; маски разрешены.
2. Поднимите VPN и убедитесь, что адреса Anthropic идут в туннель:
   ```powershell
   Find-NetRoute -RemoteIPAddress 160.79.104.10 | Select-Object -Last 1 InterfaceAlias
   ```
   Если там физический адаптер, сначала поправьте маршрутизацию VPN. Иначе Anthropic будет заблокирован всегда.
3. Установите из PowerShell от администратора:
   ```powershell
   powershell -ExecutionPolicy Bypass -File .\claude-killswitch.ps1 -Install
   ```
4. Проверьте состояние (права администратора не нужны):
   ```powershell
   .\claude-killswitch.ps1 -Status
   ```
   В колонке `Route` должен быть туннель, в `Works` — `yes`, предупреждений быть не должно.

## Команды

```powershell
.\claude-killswitch.ps1 -Install   # копия в Program Files + задача + синхронизация хоста и WSL (админ)
.\claude-killswitch.ps1            # однократная синхронизация (админ)
.\claude-killswitch.ps1 -Status    # покрытие, маршруты, WSL, последний автозапуск (без админа)
.\claude-killswitch.ps1 -Remove    # удалить правила, задачу и копию (админ)
```

После правки скрипта снова выполните `-Install`: задача запускает копию из `C:\Program Files\ClaudeKillSwitch\`.

## Если Claude перестал работать через VPN

Чаще всего VPN-клиент после обновления переименовал свой адаптер, и задача приняла его за обычную сеть. Запустите `-Status`. Если в колонке `Route` новый адаптер, а в `Works` стоит `NO: blocked`, добавьте его имя или маску в `-VpnAlias` и выполните `-Install`. Остальные случаи разобраны в `claude-killswitch-handoff.md`.

## Ограничения

- Новый сетевой адаптер закрывается через 2–5 секунд после подключения: столько нужно задаче, чтобы отработать.
- Защита работает по IP. Если у Anthropic появятся адреса вне указанных, их нужно добавить в скрипт.
- WSL в NAT-режиме заблокирован всегда. Root внутри WSL может намеренно обойти Allow, подменив адрес источника.
- Туннели, поднятые внутри Linux, Hyper-V firewall не различает.

Подробности — в `claude-killswitch-handoff.md`.
